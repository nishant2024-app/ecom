# API guide

One REST API serves the storefront, the admin panel and the future Android app.

| | |
|---|---|
| Production base URL | `https://api.example.in/v1` |
| Staging base URL | `https://api.staging.example.in/v1` |
| Local | `http://localhost:4000/v1` |
| Format | JSON (`application/json; charset=utf-8`), UTF-8 |
| Errors | `application/problem+json` (RFC 9457) |
| Spec | [openapi.json](openapi.json) (OpenAPI 3.1, generated from code). Live docs at `/docs` outside production. The introduction, tag descriptions, operation ids, security and standard error responses are added in `apps/api/src/openapi.ts`; regenerate with `pnpm --filter @dairy/api spec ../../docs/api/openapi.json`. |

## Versioning

- The major version is in the path: `/v1`. Breaking changes ship as `/v2`; `/v1` keeps working until the minimum supported Android app version no longer uses it.
- **Non-breaking changes** can ship in `/v1` at any time: new endpoints, new optional request fields, new response fields, new enum values (clients must ignore unknown fields and handle unknown enum values gracefully).
- **Breaking:** removing or renaming fields, changing types, making optional fields required, changing meanings. CI runs an OpenAPI diff on every pull request and fails on breaking changes to `/v1`.
- Deprecated endpoints return `Deprecation` and `Sunset` headers.

## Authentication

Sign in with Google and exchange the Google ID token for our tokens. Full design: [Authentication](../04-authentication.md).

| Client | How to send credentials |
|---|---|
| Storefront, admin (browsers) | Cookies set by the API (`credentials: 'include'`), plus `X-CSRF-Token` header on `POST/PUT/PATCH/DELETE` with the value of the `csrf_token` cookie |
| Android / server-to-server | `Authorization: Bearer <accessToken>` |

- Access tokens expire after 15 minutes. On `401` with code `AUTH_TOKEN_EXPIRED`, call `POST /v1/auth/refresh` once and retry the original request.
- Endpoints marked **Public** need no authentication.

## Request headers

| Header | Required | Purpose |
|---|---|---|
| `Authorization` | Bearer clients | `Bearer <accessToken>` |
| `X-CSRF-Token` | Cookie clients, unsafe methods | CSRF protection |
| `Idempotency-Key` | On endpoints marked **Idempotent** | A UUID generated by the client per logical operation |
| `Accept-Language` | Optional | `en` or `hi`; picks the language for names, descriptions and error `detail` |
| `X-Client` | Recommended | `web/1.4.0`, `android/1.0.3 (34)`, `admin/1.2.0`. For minimum-version checks and debugging. |
| `If-None-Match` | Optional | ETag from a previous response; server returns `304 Not Modified` if unchanged |

## Response headers

| Header | Meaning |
|---|---|
| `X-Request-Id` | Unique ID for this request. Quote it in bug reports; it's also in every error body. |
| `ETag` | On cacheable GETs (catalog, zones, app config) |
| `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` | Rate limit status |
| `Retry-After` | On `429` and `503` |

## Data conventions

| Type | Format | Example |
|---|---|---|
| IDs | Prefixed string, treat as opaque | `"cus_01JD3K8Q2V7M4X9TB6N5R1ZC0P"` |
| Money | Object with integer **paise** and currency | `{ "amount": 6400, "currency": "INR" }` = ₹64.00 |
| Timestamps | ISO 8601 UTC | `"2026-12-01T16:30:00Z"` |
| Business dates | `YYYY-MM-DD`, meaning a date in India (IST) | `"2026-12-02"` |
| Times of day | `HH:mm`, IST | `"05:00"` |
| Months | `YYYY-MM` | `"2026-12"` |
| Phone | E.164 | `"+919876543210"` |
| Booleans | `true` / `false` | — |
| Absent values | Field omitted or `null` as documented; never empty string as "missing" | — |

Field names are `camelCase`. Enum values are `snake_case` strings.

Display formatting (`₹1,00,000.00`) is the client's job: use `Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' })` on `amount / 100`.

## Pagination

List endpoints use **cursor pagination**:

```http
GET /v1/store/orders?limit=20
```

```json
{
  "data": [ { "id": "txn_…" } ],
  "page": { "nextCursor": "eyJpZCI6InR4bl8wMUpE…", "hasMore": true }
}
```

Next page: `GET /v1/store/orders?limit=20&cursor=eyJpZCI6…`. `limit` defaults to 20, max 100. Cursors are opaque; don't build or parse them. Admin list endpoints also accept `sort` and filter parameters documented per endpoint.

## Idempotency

`POST /v1/store/orders` requires an `Idempotency-Key` header:

- Generate a new UUID for each logical action (a tap on "Pay"). Reuse the **same** key when retrying that action after a timeout or lost connection.
- The server stores the first response for 24 hours. A retry with the same key and same body returns the stored response with header `Idempotent-Replayed: true`.
- Same key with a **different** body → `409 IDEMPOTENCY_KEY_REUSED`.
- A retry while the first request is still running → `409 IDEMPOTENCY_IN_PROGRESS`; wait and retry.

## Errors

All errors use [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457):

```json
{
  "type": "https://api.example.in/problems/out-of-stock",
  "title": "Out of stock",
  "status": 422,
  "code": "OUT_OF_STOCK",
  "detail": "Only 3 of Milk Cake 250 g box left",
  "requestId": "req_01JD3M0E7W4Y",
  "errors": []
}
```

Validation errors list each field:

```json
{
  "type": "https://api.example.in/problems/validation",
  "title": "Validation failed",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "requestId": "req_01JD3M0E7W4Y",
  "errors": [
    { "field": "/items/0/quantity", "code": "minimum", "message": "Must be at least 1" }
  ]
}
```

Clients must branch on `code`, never on `title` or `detail` (those are human text and may be translated).

### Error codes

| HTTP | `code` | When |
|---|---|---|
| 400 | `VALIDATION_FAILED` | Request body, query or params don't match the schema |
| 401 | `AUTH_REQUIRED` | No credentials |
| 401 | `AUTH_TOKEN_EXPIRED` | Access token expired → refresh and retry |
| 401 | `AUTH_TOKEN_INVALID` | Malformed or tampered token |
| 401 | `AUTH_INVALID_GOOGLE_TOKEN` | Google ID token failed verification |
| 401 | `AUTH_NONCE_INVALID` | Nonce missing, expired or already used |
| 401 | `AUTH_REFRESH_INVALID` | Refresh token unknown or expired → sign in again |
| 401 | `AUTH_REFRESH_REUSED` | Old refresh token replayed; session revoked → sign in again |
| 403 | `FORBIDDEN` | Authenticated but lacking permission |
| 403 | `STAFF_NOT_ALLOWED` | Google account isn't an active staff member |
| 403 | `CSRF_FAILED` | Missing or wrong CSRF token |
| 404 | `NOT_FOUND` | Resource doesn't exist or isn't yours |
| 409 | `CONFLICT` | State changed underneath you (e.g. editing an outdated version) |
| 409 | `IDEMPOTENCY_KEY_REUSED` | Same key, different body |
| 409 | `IDEMPOTENCY_IN_PROGRESS` | Same key, first request still running |
| 422 | `NOT_SERVICEABLE` | We don't ship to this pincode |
| 422 | `COUPON_INVALID` | 422 | The coupon code does not apply (expired, used up, below the minimum…); `detail` says why |
| `GEOCODER_UNAVAILABLE` | 503 | Map lookup service is down; ask the customer to type the address |
| `REVIEW_NOT_ALLOWED` | 403 | Reviews need a delivered order containing the product |
| `BATCH_NOT_FOUND` | 404 | Batch code not recognised on the verify page |
| `OUT_OF_STOCK` | Not enough sellable stock (detail names the product and how many are left) |
| 422 | `PRODUCT_UNAVAILABLE` | Variant not sold in this zone, or archived |
| 426 | `APP_VERSION_UNSUPPORTED` | Client older than the minimum version → force update |
| 429 | `RATE_LIMITED` | Too many requests; see `Retry-After` |
| 500 | `INTERNAL` | Unexpected server error; quote `requestId` |
| 503 | `SERVICE_UNAVAILABLE` | Overloaded or in maintenance; see `Retry-After` |

## Rate limits

Per user when signed in, otherwise per IP. Limits are generous for normal use.

| Scope | Limit |
|---|---|
| `POST /v1/auth/*` | 10 per minute per IP |
| Store reads | 300 per minute |
| Store writes | 60 per minute |
| Order placement / pay again | 10 per minute |
| Cart quotes | 120 per minute |
| Admin | 600 per minute |
| Webhooks | Not limited (signature-verified) |

## Caching

- Catalog, categories, zones and app config return `ETag` and `Cache-Control: public, max-age=60, stale-while-revalidate=300`.
- Personal data returns `Cache-Control: private, no-store`.
- Android and the PWA should send `If-None-Match` to save data on slow networks.
